lean-posix: a ctty spawn near ARG_MAX fails at the helper where the program alone would start

Found by the diff review of 53zc6j (consult round 20261114-190528-3f54, sol). A `trySpawn ... (ctty := true)` starts the helper `lean-posix-ctty` with its protocol arguments, every PATH candidate of the program (`c/spawn.c`, `spawn_ctty`) and then the program's own arguments, all beside the program's environment. The candidates are one path per PATH entry, so a long PATH adds a few kilobytes. An argument list and environment that `posix_spawn` of the program would accept, within that margin of macOS's ARG_MAX (1 MiB), then fails at the stage `ctty helper` with E2BIG, though the program itself would have fit. Without `ctty` nothing changes.

Options: hand the helper only the program's name and the value of PATH, and let it build the candidates (which duplicates `Posix.candidates`, whose properties are stated in Lean); or send the candidates on a second descriptor the helper reads before its exec; or document the margin in `trySpawn`'s doc comment and keep the protocol. A test would spawn, with and without `ctty`, a program whose arguments and environment come within that margin of ARG_MAX, and expect both to start. Changing the protocol bumps its version (`--lean-posix-ctty-v2`), which every consumer that installs the helper rebuilds with.
