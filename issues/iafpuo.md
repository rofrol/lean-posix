lean-posix: decide whether waitOutcome should report a traced child's stop instead of passing it by
`Posix.waitOutcome` (`Posix/Spawn.lean`, added for z2mn4g) loops past a wait status whose low 7 bits are 0x7f, which `waitpid(pid, &s, 0)` returns only for a traced child, and resumes nothing; a process that traces its own child (PT_TRACE_ME) would block there with the child stopped. Its doc comment states this. lean-posix has no ptrace binding and no known consumer traces a child, so nothing hits it today. Raised by sol in review round 20261109-082642-8925 (argon agreed). Options: leave it documented as it is | add a stopped outcome to `ExitOutcome` (a public contract change for rr2's harness) | make the stop an error the wait throws.
