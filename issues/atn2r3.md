lean-posix: move the Kqueue bindings into the C file, with <sys/event.h> instead of hand-declared struct kevent

Plan from consult round 20261109-174150-a3d1 (sol, argon agreed), after the owner on 2026-11-09 lifted the rule that lean-posix's C lives only in `@[extern c inline]` expressions and asked where non-inline is better. The gain is compiler-checked system declarations: every struct layout and constant is written by hand today, and two such mistakes were found that day (flags 0x14 documented as SA_RESTART | SA_RESETHAND, signal 18 documented as SIGCONT). Checked by the session: the Lean toolchain's clang compiles a C file that includes <sys/event.h>, <signal.h>, <termios.h>, <libproc.h> and <lean/lean.h> with `-I<lean prefix>/include -I<lean prefix>/include/clang -isysroot $(xcrun --show-sdk-path)`; without -isysroot no system header is found. Conventions: exported symbols `lean_posix_*`, helpers and state `static`, every Lean signature and documented behavior unchanged, `lake test` passes.

Work: every expression in `Posix/Kqueue.lean` (watchSession, kqWaitUntil, catchSignals, nextSignal, watch, awaitExits, watchExit, the others) becomes a function in `c/kqueue.c` using `struct kevent`, `EVFILT_*`, `EV_*`, `NOTE_*` by name; the Lean side `@[extern]`. Remove the module header's list of numbers that the C now names. Depends on the C-file scaffolding item. Check: `lake test` (kq, watch, signal tests), each with its producer and consumer acknowledging through pipes, no sleeps.
