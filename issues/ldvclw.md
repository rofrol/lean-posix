lean-posix: Term.lean names its sigaction flags 0x14 SA_RESTART | SA_RESETHAND, which on macOS is SA_NODEFER | SA_RESETHAND

Met while adding `catchSignals` (item j3aw7s). `Posix/Term.lean`, the doc comment of `termRaw`, says "SA_RESTART | SA_RESETHAND 0x14", and op 1001 installs its handler with flags 0x14. macOS's `<sys/signal.h>`: SA_RESTART 0x2, SA_RESETHAND 0x4, SA_NODEFER 0x10, so 0x14 is SA_RESETHAND | SA_NODEFER: system calls interrupted by these signals are not restarted, and the handler is not blocked while it runs (it resets itself, so a second signal gets the default). Decide which the handler means: correct the comment to the flags in use, or the flags to the comment (SA_RESTART would change what interrupted calls in the terminal program do, a behavior change for consumers). Check: `lake test`'s terminal tests (`tests term-signal`, `tests term-motion-signal`).
