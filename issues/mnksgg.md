lean-posix: the lockDir EINTR test cannot tell lf_setlock's abort-safe sleep from another interruptible wait inside flock

Found while doing abcwsi (commit "tests: observe lockDir's waiter in flock and cite XNU for pthread_kill's ordering"). `inFlock` (`Tests/Main.lean`) sees the waiter's main thread inside the `flock` system call (saved user `x16` = 131) in a wait that is not uninterruptible (`thread_info` `TH_STATE_WAITING`). XNU exports no wait channel (`uu_wmesg` is in neither `bsd/kern/kern_sysctl.c` nor `bsd/kern/proc_info.c`, xnu-12377.1.9), and `TH_STATE_WAITING` does not tell `THREAD_ABORTSAFE` from `THREAD_INTERRUPTIBLE`. If the wait seen were an interruptible but not abort-safe one inside APFS's `VNOP_ADVLOCK` (closed source), `thread_abort_safely` would only mark the thread (`osfmk/kern/thread_act.c` 566-569), and if the holder ended before `lf_setlock` slept, the unfixed `lockDir` could take the lock and pass. The test's doc comment states this under "Not proven"; consult round 20261109-174228-173f (sol, argon) raised it.

Does this documented limit stand, or is a stronger observation wanted?
