lean-posix: start children with posix_spawn instead of fork, and a ctty through a small helper
From the user's request on 2026-11-09 to add "we do not use fork" to the Lean skill (consult round 20261109-082926-1c79, sol and argon). `trySpawn` (`Posix/Spawn.lean`) forks in a multithreaded Lean process; its child calls only async-signal-safe functions, but on macOS `fork` runs libSystem's atfork handlers before the child's own code, and in Odin on macOS a fork while another thread was inside libnotify's os_once killed the child before exec (agent-kit's odin skill). Not yet reproduced in Lean. Proposed: `posix_spawn` with `POSIX_SPAWN_SETSID` and `POSIX_SPAWN_CLOEXEC_DEFAULT` for every spawn without `ctty` (exec's error comes back from the call, so the report pipe and its lock may go); for `ctty`, which no public spawn attribute gives on macOS, spawn a small single-threaded helper executable that does `setsid`, `ioctl(0, TIOCSCTTY, 0)` and `execve`, keeping `SpawnFailure`'s stages. First a diagnostic stress run of today's `trySpawn` while other threads call into libSystem, to know whether Lean meets the failure at all. Note: Lean's own `IO.Process.spawn` forks too (`process.cpp.o` in libleanrt.a of nightly-2026-10-25 imports `_fork`, not `posix_spawn`), so it is no alternative. A helper executable is a new deployment piece of the library: needs the owner's approval.

Decided by the user 2026-11-09: approved, the helper executable included. Order decided with the models (consult round 20261109-174629-3483): the diagnostic is split out as its own item and runs first, before any migration, to keep baseline evidence; a design item settles the helper's packaging before this one. Checked by the session: the macOS SDK's <spawn.h> has no controlling-terminal attribute (POSIX_SPAWN_SETSID only makes a session), so `ctty` needs the helper; a private `_np` SPI is not used. This item writes the spawn path directly in `c/spawn.c` on `posix_spawn`, so the fork child is never ported, and ends with no `extern c inline` in `Posix/` except ones whose comment says why. A failed diagnostic reproduction does not cancel it.
