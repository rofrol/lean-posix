lean-posix: assert the inline expressions' hand-written function declarations against the SDK in c/abi.c

Found while doing zcyzdk. `c/abi.c` checks the numbers and struct layouts the `@[extern c inline]` expressions write by hand, but not the `extern` function declarations each expression carries (for example `extern long read(int, void*, unsigned long)`, `extern int fstat64(int, void*)`, `extern unsigned long long clock_gettime_nsec_np(int)`): a wrong return or parameter type there is still unchecked undefined behavior (AGENTS.project.md, "Trust, effects and failure"). Work: for each declared function, a `_Static_assert(__builtin_types_compatible_p(__typeof__(&f), <the expression's type>), ...)` in `c/abi.c` (pointer parameters the expressions declare as `void*` compared as such, or the expression's declaration corrected to the SDK's type where they differ), and the AGENTS.project.md sentence updated. Check: `lake build`; a mutated declaration fails to compile.
