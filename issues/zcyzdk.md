lean-posix: move the termCtl handler and terminal state into a C file built by Lake, with system headers and _Static_assert checks

Plan from consult round 20261109-174150-a3d1 (sol, argon agreed), after the owner on 2026-11-09 lifted the rule that lean-posix's C lives only in `@[extern c inline]` expressions and asked where non-inline is better. The gain is compiler-checked system declarations: every struct layout and constant is written by hand today, and two such mistakes were found that day (flags 0x14 documented as SA_RESTART | SA_RESETHAND, signal 18 documented as SIGCONT). Checked by the session: the Lean toolchain's clang compiles a C file that includes <sys/event.h>, <signal.h>, <termios.h>, <libproc.h> and <lean/lean.h> with `-I<lean prefix>/include -I<lean prefix>/include/clang -isysroot $(xcrun --show-sdk-path)`; without -isysroot no system header is found. Conventions: exported symbols `lean_posix_*`, helpers and state `static`, every Lean signature and documented behavior unchanged, `lake test` passes.

Approved by the owner on 2026-11-09 (the handler move: a true `void handler(int)` instead of casting `lean_posix_term_ops`, documented as accepted debt in wnex37's commit f2abbae; Odin rejected as a compiler every consumer would need). Decided by the user 2026-11-09: the macOS SDK (Xcode or the Command Line Tools) becomes a build requirement of lean-posix and its consumers (rr, rr2, lean-tui, ffprogress); README says so.

Work: the Lake scaffolding (a `target` compiling `c/*.c` with the toolchain's clang, flags above, the SDK path found at build time and never committed, `-Wall -Wextra -Werror`, and an `extern_lib`); `c/term.c` with the handler, `saved`, `on` and the escape strings, real `struct termios`, `SIGTSTP` and `SA_RESETHAND | SA_NODEFER` by name; `termCtl` through `@[extern "lean_posix_term_ctl"]`. A header `c/abi.c` (or the same file) with `_Static_assert` for every number the remaining inline expressions still use that has a header name (signals, SA_* flags, EVFILT_*, EV_*, O_*, F_*, errnos, ioctl numbers, `sizeof(struct kevent)`, `sizeof(struct winsize)`), so a wrong hand-written constant fails the build. Record the ruling in `DECISIONS.md` and update `AGENTS.project.md` and the lakefile's doc, which say there is no C file. Check: `lake test` (term and signal tests), `nm` shows the handler as a plain C function, and one consumer (rr2, in a scratch copy with its lean-posix input pointed at the commit, nothing pushed) builds and passes `lake test` from a clean `.lake`.
