lean-posix: openPty's slave is inherited by every child, so a spawn in another thread before the caller closes it keeps the pty open

Raised in consult round 20261109-171902-3afb (argon), checked in the code while finishing jd6rjr: `openPty` (`Posix/Pty.lean`) opens the slave without O_CLOEXEC, and its doc comment now states that every child inherits it until it is closed. A `trySpawn`/`spawn` or Lean spawn in another thread between `openPty` and the caller's `close s` gives that unrelated child the slave at its own number, so the master never sees EOF/EIO while that child lives, the same failure jd6rjr removed for the master. Callers in this repository hand the slave to a child as 0, 1 or 2 (`spawn ... s s s`, which dup2s it, clearing close-on-exec on the copy), and `loginTty` runs in a forked child before exec, so a close-on-exec slave would likely still serve them; whether any consumer (rr2, rr, lean-tui) relies on the slave staying open across exec at its own number is not checked. Changing it is a public contract change (AGENTS.project.md: what a declaration leaves inherited), needing the owner's approval and each consumer's check. Work: open the slave with O_CLOEXEC, update the doc comment, and turn the `inherited` test in `Tests/Main.lean` into one that the slave is not inherited either.
