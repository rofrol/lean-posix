lean-posix: move catchSignals' handler into c/ as a true void handler(int)

Found while doing zcyzdk. `catchSignals` (Posix/Kqueue.lean) still installs `lean_posix_signal_caught`, a Lean-exported `uint32_t (uint32_t)`, cast to `void (*)(int)` inside its inline expression (`(void (*)(int))lean_posix_signal_caught`), with a hand-written `struct { void (*h)(int); unsigned m; int f; }` for `struct sigaction`. Calling a function through an incompatible pointer type is undefined behavior (C11 6.3.2.3p8), the same debt zcyzdk removed from `termCtl`. Work: a `static void` no-op handler in a `c/*.c` file and the `sigaction` loop there with `<signal.h>` and `<sys/event.h>`, bound with `@[extern "lean_posix_..."]`, its Lean signature and doc contract unchanged; drop the now unused Lean export. Check: `lake test` (the signals and lock-dir-signal tests), `nm` shows the handler as a plain C function and no `lean_posix_signal_caught`.
