lean-posix: results encoded as high bits or "large numbers" as Except values

Several public bindings return a `UInt32` whose meaning a caller must decode from the doc comment: `openPty` and `openEvents` give "a large number" on failure, `lockDir` gives -1, `watchSession` sets the high bit when the process had already exited, `watch` or-s 0x80000000 with the errno, `kqWait`/`kqWaitFor` give a bit mask with 0x80000000 for failure, `loginTty` gives "a large number", and `spawnRaw`/`lockRaw`/`processStartRaw` are public with packed results although `trySpawn`, `lockFile` and `processStart` decode them. Proposal: return `Except UInt32 _` (or a small structure, e.g. the kqWait events as a record of booleans and arrays) from the public declarations, make the raw ones private, and state as theorems the pure decoders' properties (e.g. `trySpawn`'s stage decoding covers every stage `spawnRaw` writes; `candidates` gives `[name]` for a name with `/` and one path per PATH entry otherwise). One item per module is a reasonable split. Public contract change for rr, rr2 and lean-tui; needs the owner's approval.

Why, from consumers' code (consult round 20261109-170703-dda6, sol and argon, call sites checked by the session on 2026-11-09): rr and rr2 decode the packed results by hand about twenty times (`&&& 0x80000000`, `&&& 0x7fffffff`, e.g. rr/TuiMain.lean:287-291, rr2/Rr2/Viewer.lean:157-161, rr2/Rr2/Run.lean:255-282); `openPty`'s failure is tested three different ways (rr/Watcher/Command.lean:270 `== 0xffffffff`, rr/Screens/Main.lean:243 `≥ 0x80000000`, rr2/Tests/Proc.lean:151 `> 0xFFFF`), all correct today only because the C gives -1; `watchSession`'s caller must strip its "already exited" bit before using the kqueue (rr/Watcher/Session.lean:291-295). What it would not fix: a result thrown away with `discard` (rr/TuiMain.lean:1293, rr/Watcher/Command.lean:154) stays possible with `Except`. Scope the models agreed on: per module, starting with `watch`/`openPty`/`watchSession`; `watchSession`'s bit is a state of a success, so it becomes a record (descriptor and exited flag), not an error; `kqWait`'s mask later. They disagreed on keeping the raw API beside the typed one during migration (sol: yes, with a removal milestone; argon: one clean break, since there are no outside users) and on the decoder theorems (sol: they do not prove the C; argon: drop them).
