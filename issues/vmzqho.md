lean-posix: the kq test hangs when the process's exit comes before its output's end

Seen in item o3bkwn's `lake test` run (2026-11-09): the `tests` process blocked for good in `kq` (`sample` showed `lp_lean_x2dposix_kq` in `kevent`), and `lskq -p <pid>` showed its watchSession kqueue holding only the directory's VNODE watch: the read filter had been removed by `unwatchRead` and the one-shot EVFILT_PROC exit event was gone. `head` (the child) was a zombie. So `eventsUntil k 1 8` (Tests/Main.lean:235) had consumed the exit event (2) before the end of output (1), its check still passed (the last event was 1), and `nextEvent k` at Tests/Main.lean:238, after `unwatchRead`, waited for an exit that had already been reported. The order of the exit and the pipe's EOF is not fixed by the kernel, so the test assumes an ordering that does not hold. A rerun is not evidence either way. Fix in the test: collect the events until both the output's end and the exit have come (in either order) and check both, instead of expecting the exit after `unwatchRead`; or check `nextEvent`'s contract ("2 the process exited") against `evs` too. Small, test-only, no contract change.
