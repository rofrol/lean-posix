Kqueue: a wait with a timeout, so a full-screen program can redraw a clock

Asked by rr2 (its issue d7oqbd; the owner approved on 2026-11-09 the option "add a timeout to lean-posix's kqWait"). rr2-view shows a running run's wall time and should redraw it every second while one runs; its loop is one blocking `Posix.kqWait`, which (`Posix/Kqueue.lean`) waits with no timeout (only `poll` with a zero one), and there is no timer filter. `Posix.alarm`'s SIGALRM is one of the signals `Posix.Term` handles by restoring the terminal and dying, so it is no way out. Wanted: a wait that returns after at most a given number of milliseconds with nothing happened (a distinct bit in the mask or an empty result, documented), using kevent's own timeout, e.g. `kqWaitFor (kq : UInt32) (ms : UInt32)`, keeping `kqWait`'s contract for its callers (rr). EINTR handling must not stretch the deadline unboundedly (recompute the remaining time or document what happens). With a test: a wait with a short timeout and no event returns with nothing; an event that comes first is reported.

The timeout's user is a read-only observer of the wall clock (an external producer, AGENTS.md Rule 10), not a retry. Base it on main (73854fa, which has csgol3 and p7gfgy) and push a `pin/<sha12>` tag for the result so rr2 can pin it.
